# 家計・資金管理アプリ — 現金がマイナスにならない資金繰り

マネーフォワード ME のデータを取り込み、**計画（利用上限）と実績を比べながら、口座残高の先行きを日次でシミュレーション**する Web アプリです。
個人のコスト削減から始めて、将来は中小企業の資金繰り管理への展開を想定した設計になっています。

## コンセプト：2つの独立した管理 ＋ 資金ショート予測

```
【A】資金繰り（残高）… 残高 ＝ 現金・口座の入出金のみで計算
      ・カード利用は残高に入れない（引落日に🔁定期の予定として反映）
      ・二重計上が構造的に起きない
【B】カード利用管理 … カード別に月の上限 vs 利用実績で使いすぎを監視（残高とは非連動）

🚨 資金ショート予測
      今日の残高から「定期の予定 ＋ 現金予算の日割り」で月末まで日次シミュレーション。
      最低残高とその日付を算出し、安全ライン（設定値）を割る予測が出たら警告。
```

## 3階層の資金管理

```
📅 年次   → 年初残高 ＋ 月別収支の積み上げ。過去=実績 / 当月=実績+残り予定 / 未来=計画
🗓 日次   → 資金繰り表。実績と予定（薄い斜体）が同じ表に並び、残高の先行きが見える
🎯 月次   → 計画（上限）は手入力 or エクセル/CSV一括アップロード、実績はMF CSV取込
```

## タブ構成

| タブ | 内容 |
|------|------|
| 📊 ダッシュボード | 安全ライン警告 / 今日あと使える額（変動費） / 残高と月末予測 / 最低残高予測 / 計画vs実績vs着地 |
| 🗓 日次 | 資金繰り表。かんたん（入金・出金・残高）⇔ 全項目（項目マスタの列展開）切替。行タップで内訳・編集 |
| 🧾 明細 | 対象月の明細。フィルタ（現金/口座/カード/未分類）、行タップで編集・削除・項目変更 |
| 💳 カード | カード別の月上限 vs 利用実績（🟢🟡🔴）。口座残高とは非連動 |
| 📅 年次 | 年初残高・安全ラインの設定、月別積み上げ、年末残高予測、ショート月の警告 |
| 🎯 計画 | 変動費（現金＋カード）の上限と入金目標。エクセル/CSV一括アップロード対応 |
| 🔁 定期 | 毎月の固定的な出入り（ローン・習い事・カード引落・給与）。予定は日次と残高予測に自動反映 |
| 📥 取込 | MF ME の CSV 取込（Shift-JIS/UTF-8自動判定・重複防止・手段の自動分類） |
| ⚙️ 項目 | 入金・出金の項目を画面から自由に追加・編集（日次一覧の列になる） |

### 固定費と変動費の分離（予測の精度の要）

- **変動費** ＝ 現金支出 ＋ カード利用。計画の「現金上限＋カード上限」が予算。
  「今日あと使える額」と着地予測は変動費だけを日割り計算するので、月初の固定費で警告が誤爆しない。
- **固定費** ＝ 口座の引落・振込。🔁定期マスタの予定と突合して「済 ✓ / 予定 / 未取込⚠」を管理。

### 定期予定の自動消し込み

定期はDBに明細を生成せず「予定」として表示します。MF取込や手入力で**同じ項目の実績が入ると、その月の予定は自動で実績に置き換わります**（項目未設定の場合は名称の部分一致で突合）。予定日を過ぎても実績が無い場合は「未取込⚠」で知らせます。

### MF CSV の手段自動分類

| 保有金融機関 | 分類 |
|---|---|
| 登録済みカード名と一致 | カード利用（残高外・カード別集計） |
| 「カード」を含む | カード利用（未登録カード） |
| 現金・財布・ウォレット | 現金（残高に反映） |
| それ以外（銀行など） | 口座（残高に反映） |

## 使い方

1. `index.html` をブラウザで開く（スマホ対応）→ メールアドレスでログイン
2. ⚙️項目 で自分の列構成を作る（給与・現金・ローン・JCB…）
3. 📅年次 で年初残高と安全ラインを設定
4. 🔁定期 でローン・習い事・カード引落・給与を登録
5. 🎯計画 で現金・カードの上限を設定（CSV一括も可）
6. 📥取込 に MF ME の CSV をドロップ
7. 📊ダッシュボード と 🗓日次 で「今日使える額」と「残高の先行き」を毎日確認

## データ構成（Supabase / PostgreSQL）

すべて `expense_` 接頭辞。**全テーブル user_id 列＋RLS「自分の行のみ」**で、ユーザーごとに完全分離（マルチユーザー＝中小企業展開の土台）。

| テーブル | 役割 |
|---------|------|
| `expense_categories` | 項目マスタ（区分・グループ・色・並び） |
| `expense_year_settings` | 年次設定（年初残高・**安全ライン min_balance**） |
| `expense_monthly_plans` | 月次計画（現金/カード上限・入金目標） |
| `expense_category_budgets` | カテゴリ別の上限 |
| `expense_transactions` | 実績明細（MF/手入力）。`payment_type` で現金/口座/カードを区別 |
| `expense_recurring` | 定期マスタ（毎月N日・金額・**card_id＝カード引落の対象**） |
| `expense_cards` | カードマスタ |
| `expense_card_limits` | カード別・月別の利用上限 |
| `expense_import_log` | 取込履歴 |

- ユニーク制約はすべて `(user_id, …)` 単位。upsert は `onConflict:"user_id,…"`。
- 公開キー（`sb_publishable_...`）はブラウザ用の公開鍵で、コードへの埋め込みは想定どおり。
- 日付処理はすべて端末ローカル（日本時間）基準。

## ロードマップ

- **Phase 1（現在）**: 自分のコスト削減 — 計画 vs 実績、資金ショートの事前警告
- **Phase 2（将来）**: 中小企業向けの資金繰り管理 — 複数ユーザー・承認フロー・複数口座・入金サイト管理
